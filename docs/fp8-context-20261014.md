# Arkey FP8 cache and client smoke — RTX 5090, 2026-10-14

Arkey's managed vLLM setup now uses FP8 KV cache with automatic context sizing.
The local Qwen3.8-27B-NVFP4-NVIDIA checkpoint still uses NVFP4 weight quantization;
KV precision is a separate setting. vLLM is 0.31.0 on the 32 GB RTX 5090.

| Managed configuration | Total context reported by the engine |
| --- | ---: |
| BF16 KV (`auto`) | 94,864 |
| FP8 KV (`fp8`) | 244,608 |

Both launches requested `--max-model-len auto`, BF16 compute dtype, 0.90 GPU
memory utilization, one sequence and 2,048 maximum batched tokens. Prefix caching
was enabled and speculation was off. Arkey derives client context from the loaded
server's `/v1/models` result. Its output reserve is one quarter of context, capped
at 32,768; at 244,608 this leaves 211,840 tokens before other client margins.

The [selected runtime states and sanitized logs](evidence/fp8-context-20261014/)
record the result. The FP8 engine selected FLASHINFER attention, reported 7.84 GiB
available KV memory, and fitted 244,608 against the model limit of 262,144.
BF16 used FLASH_ATTN. Therefore the difference includes backend memory behavior;
it is not a controlled measurement of cache element size alone. The model also
has separate recurrent state. No additional KV-scale calibration was performed.

This does not supersede the earlier [262K capacity experiment](https://github.com/JulianAbeleda/BoltBeam/blob/main/docs/quant-comparison-rtx5090-20261014.md#long-context-with-fp8-kv),
which used **0.95** GPU memory utilization and explicitly requested 262,144.
That experiment exercised long prompts; this Arkey run verifies startup capacity
and short client operations. It does not establish full-window quality or stability.
FP8 and llama.cpp's Q8_0 are different 8-bit cache formats.

## Client checks

- Codex returned `ARKEY_FP8_INSTALLED_OK`.
- Kimi returned `ARKEY_FP8_OK`; a file-reading tool round trip returned `maple-4827`.
- Charm Crush v0.89.0 returned `ARKEY_CRUSH_OK`; its file-reading round trip also
  returned `maple-4827`. Its generated config used 244,608 context and 32,768
  default maximum output tokens. Crush is available in Arkey's client menu.

These use the same loaded local vLLM server through MoonBridge. The user's
observation that Crush feels instant is qualitative feedback, not a latency
measurement or an AWQ/NVFP4/llama ranking. No new matched replay was run here.

successful client testing. Evidence omits environment/config secrets and replaces
home paths and session identifiers; checksums cover the sanitized copies.
